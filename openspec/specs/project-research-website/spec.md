# project-research-website Specification

## Purpose

为项目提供一个中文静态多页网站，集中展示无障碍出行项目的背景、提案、团队、进展和数据收集计划，使项目材料能够通过 GitHub Pages 被清晰、稳定地访问。

## Requirements

### Requirement: 首页展示项目总览
网站 SHALL 提供中文首页，并展示项目背景与问题、项目提案、开发团队和项目进展四个核心部分。

#### Scenario: 用户打开首页
- **WHEN** 用户访问网站根路径
- **THEN** 页面显示项目背景与问题、项目提案、团队信息和项目进展，并提供数据收集计划和数据收集结果页面的独立导航入口

#### Scenario: 用户阅读项目进展
- **WHEN** 用户查看首页的项目进展部分
- **THEN** 页面按阶段展示问题发现、项目提案、调研设计、数据收集、需求归纳和方案迭代等内容及其状态

### Requirement: 展示开发团队信息
网站 SHALL 支持为每位团队成员展示姓名、头像和中文纯文本个人介绍。

#### Scenario: 用户查看团队成员
- **WHEN** 用户浏览首页的开发团队部分
- **THEN** 每位成员都显示姓名、头像和个人介绍，且单个成员信息彼此清晰区分

#### Scenario: 成员头像缺失
- **WHEN** 某位成员尚未提供头像
- **THEN** 页面仍显示姓名和个人介绍，并使用稳定的占位显示而不破坏页面布局

### Requirement: 展示数据收集计划
网站 SHALL 提供独立的数据收集计划页面，并分别展示访谈计划、访谈问题、问卷计划和问卷内容。

#### Scenario: 用户访问数据收集计划
- **WHEN** 用户从导航或首页入口进入数据收集计划页面
- **THEN** 页面显示访谈和问卷的目标、对象或说明，以及对应的完整文本内容

#### Scenario: 数据收集内容较长
- **WHEN** 访谈问题或问卷内容超过首屏可见范围
- **THEN** 页面仍保持章节层次、可读性和页面导航，不要求内容压缩成图片

### Requirement: 展示数据收集结果
网站 SHALL 提供独立的数据收集结果页面，按调研原始材料的章节结构展示问卷数据分析和亲和图分析，包括数据概览、关键发现、方法说明、原始数据提取、制作过程、主题分类及各章节的结论。

#### Scenario: 用户访问数据收集结果
- **WHEN** 用户从导航或首页入口进入数据收集结果页面
- **THEN** 页面显示问卷数据分析和亲和图分析两个部分，并保留原文的次级分节顺序

#### Scenario: 用户阅读图表
- **WHEN** 用户查看页面中的任一图表
- **THEN** 图表配有可见的图注和替代文本，图注内容与图片自带的标题一致

#### Scenario: 用户查看长图或超宽图
- **WHEN** 用户查看亲和图原始记录或主题分类图
- **THEN** 页面以受限尺寸显示可读的缩略版本，并提供在新标签打开原尺寸图片的入口

#### Scenario: 用户阅读主题分类结论
- **WHEN** 用户查看亲和图的主题分类
- **THEN** 页面表述为 15 个主题归入 5 个高级主题，并说明另有 1 个主题不隶属于任何高级主题

### Requirement: 结果页面提供站内导航
数据收集结果页面 SHALL 提供与其他页面一致的主要导航，以及指向本页各章节的页内目录。

#### Scenario: 用户使用页内目录
- **WHEN** 用户点击页内目录中的章节链接
- **THEN** 页面跳转到对应章节，且目录在当前页面中标记为活动状态

### Requirement: 支持多页导航
网站 SHALL 在首页、数据收集计划页面和数据收集结果页面之间提供一致、可理解的中文导航。

#### Scenario: 用户切换页面
- **WHEN** 用户点击数据收集计划或数据收集结果导航项
- **THEN** 浏览器打开对应的独立页面，且用户可以返回首页

#### Scenario: 当前页面导航状态
- **WHEN** 用户位于某个页面
- **THEN** 导航能够清楚表示当前页面，并保持主要导航项的位置和名称在所有页面一致

### Requirement: 保持静态内容边界
网站 SHALL 仅展示预先整理并获受访者同意的文本和图片内容，不提供在线访谈提交、问卷提交、数据库存储或动态统计功能。

#### Scenario: 用户浏览数据收集页面
- **WHEN** 用户查看访谈或问卷内容
- **THEN** 页面展示内容说明和题目文本，但不显示在线提交控件或要求用户上传数据

#### Scenario: 用户浏览数据收集结果页面
- **WHEN** 用户查看问卷分析或亲和图分析
- **THEN** 页面展示预先整理的图表和结论文本，但不提供筛选、重新统计或导入数据的交互控件

#### Scenario: 用户浏览网站全部页面
- **WHEN** 用户访问首页、数据收集计划页面或数据收集结果页面
- **THEN** 页面只展示预先整理的内容，不提供在线提交、数据导入或动态重新统计的控件

### Requirement: 适配 GitHub Pages 托管
网站 SHALL 能够作为无需后端服务的静态站点部署到 GitHub Pages，并使用中文界面和现代、清晰、朴素的视觉表达。

#### Scenario: 静态部署
- **WHEN** 网站文件被发布到 GitHub Pages
- **THEN** 用户可以直接访问首页和数据收集计划页面，不依赖运行中的应用服务器或数据库

#### Scenario: 小屏幕访问
- **WHEN** 用户使用手机或窄屏窗口访问任一页面
- **THEN** 内容、导航、团队信息和长文本保持可阅读，且不出现横向溢出
