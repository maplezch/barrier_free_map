# Design

## Context

项目当前是一个以问题陈述和调研材料为主的文档型仓库，没有现成的网站代码或前端框架。网站需要作为 GitHub Pages 静态站点发布，内容主要来自现有问题陈述以及后续整理好的访谈和问卷文本。

## Goals / Non-Goals

**Goals:**

- 建立首页和数据收集计划页两个稳定的内容入口。
- 让首页适合快速了解项目，让调研页适合阅读较长的访谈和问卷内容。
- 使用中文、现代、清晰、朴素的视觉系统，保证桌面端和手机端可读。
- 让团队成员头像、姓名和介绍可以通过静态资源持续维护。
- 为项目进展提供可更新的阶段时间线。
- 使站点不依赖后端、数据库或构建服务即可部署到 GitHub Pages。

**Non-Goals:**

- 不实现在线访谈或问卷提交。
- 不实现数据库、账号、动态数据接口或调研结果页面。
- 不展示未经整理的隐私数据。
- 不制作项目 Logo、封面图或路线示意图。
- 不引入复杂的前端框架或不必要的第三方服务。

## Decisions

### 多页静态结构

采用首页和独立数据收集计划页。首页承担项目总览，数据收集计划页承载访谈和问卷的长文本；通过统一顶部导航互相跳转。相比单页滚动结构，多页结构能减少首页长度，并为未来增加项目文档提供稳定边界。

建议页面路径为：

- `/index.html`：项目背景、项目提案、团队和项目进展
- `/research-plan.html`：访谈计划、访谈问题、问卷计划和问卷内容

### 原生静态文件优先

使用 HTML、CSS 和少量原生 JavaScript（仅在确有交互需要时）。不依赖后端和第三方组件库，以降低 GitHub Pages 部署复杂度，并让后续维护者可以直接修改内容。

备选方案是使用静态站点生成器，但当前网站规模较小、内容以手工整理的中文文本为主，直接使用静态文件更容易理解和发布。

### 统一内容框架

所有页面使用一致的页眉、导航、页脚、内容最大宽度和标题层级。首页按“问题 -> 提案 -> 团队 -> 进展”组织，调研页按“访谈 -> 问卷”组织；较长内容使用章节标题、编号和可选的折叠分组，以保持浏览效率。

### 朴素视觉系统

采用浅色背景、深色正文、单一稳重的强调色和少量边框/阴影，避免装饰性背景和过度动画。团队成员使用规则一致的信息块，头像采用固定比例并在缺失时显示占位内容。页面使用响应式布局，在窄屏时将导航和多列内容调整为纵向排列。

### 进展时间线

初始时间线固定为以下阶段，并允许通过静态文本修改状态：问题发现、项目提案、调研设计、数据收集、需求归纳和方案迭代。阶段状态使用文字标签而非只依赖颜色，确保信息在小屏幕和辅助技术环境中仍可理解。

### 内容与资源分离

页面结构、视觉样式和团队头像分开存放。建议将成员图片集中放在 `assets/images/`，将共享样式放在 `assets/css/`；访谈与问卷文本直接放入对应 HTML 页面，便于审阅和提交。后续内容增加时，优先保持现有页面路径和导航名称不变。

### GitHub Pages 兼容性

页面之间使用相对链接，资源使用相对路径，避免依赖本地绝对路径。发布前在仓库子路径和直接文件访问场景下检查导航、图片和样式是否正常加载。

## Risks / Trade-offs

- [长文本降低阅读效率] -> 使用清晰的章节层级、页内目录和折叠分组，避免把内容制作成不可搜索的图片。
- [GitHub Pages 子路径导致资源失效] -> 所有页面使用相对资源路径，并在实际发布路径下验证。
- [团队头像尺寸不一致] -> 使用固定比例容器和统一裁切规则，缺失头像显示占位状态。
- [颜色对比不足] -> 使用高对比正文和链接颜色，并通过键盘焦点样式保持交互可见。
- [后续内容增长导致页面过长] -> 保持首页只展示项目总览，调研材料集中在独立页面；未来可在不改变现有路径的前提下继续拆分子页面。
- [静态内容更新依赖人工维护] -> 采用直观的 HTML 内容分区和稳定的资源目录，减少更新时对代码结构的要求。

## Migration Plan

1. 创建静态页面、共享样式和资源目录，并将现有问题陈述转换为首页内容。
2. 将访谈问题和问卷内容整理到数据收集计划页。
3. 添加团队成员信息、头像资源和初始项目进展状态。
4. 在本地检查页面链接、窄屏布局、缺失图片和文本可读性。
5. 推送到 GitHub 仓库并启用 GitHub Pages。
6. 若发布异常，先回退到上一版静态文件；由于不涉及数据库和迁移，回滚只需恢复页面资源。
